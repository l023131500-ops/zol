# KioskFleet — פלטפורמת ניהול קיוסק מרחוק

מערכת מלאה להפעלה, ניהול ושליטה מרחוק על צי מכשירי **קיוסק (Android)**.
כל לקוח מקבל שם משתמש, סיסמה ומכסת מכשירים, נועל כל טאבלט על האתר שלו, ושולט
בכל מכשיר בנפרד **לפי מספר סידורי** — אתחול, רענון, החלפת אתר, כיבוי/הדלקת מסך
וניטור — הכל מדפדפן אחד ובזמן אמת.

> נבנה מתוך אפליקציית ה‑Kiosk המקורית (`giftkal-kiosk`) והורחב למוצר SaaS כללי
> רב‑לקוחות.

## מה יש כאן

```
kiosk/
├─ server/        # שרת Node.js: API + WebSocket + מסד נתונים + אתר תדמית + קונסולת ניהול
│  ├─ src/        #   auth · devices · admin · agent · realtime hub
│  └─ public/     #   דף הנחיתה (index.html) + הקונסולה (console.html)
├─ android/       # אפליקציית KioskFleet Agent (Kotlin) — נשלטת מרחוק
└─ docs/          # מדריכים בעברית: משתמש · מנהל‑על · פריסה
```

## ארכיטקטורה

```
   ┌─────────────┐   HTTPS / WSS    ┌────────────────────┐   WSS/HTTPS   ┌──────────────┐
   │  טאבלטים    │ ───────────────▶ │   שרת KioskFleet   │ ◀──────────── │  דשבורד ווב  │
   │  (Agent)    │  heartbeat +     │  Express + ws +    │  שליטה בזמן   │  לקוח / אדמין │
   │             │  פקודות בזמן אמת │  SQLite            │  אמת          │              │
   └─────────────┘                  └────────────────────┘               └──────────────┘
```

- **מכשיר** נרשם עם קוד חד‑פעמי → מקבל `device_token` ייחודי → מתחבר ב‑WebSocket
  ומדווח סטטוס. פקודות נדחפות אליו מיידית, או ממתינות בתור עד שיחזור לרשת.
- **לקוח** מנהל רק את המכשירים שלו, עד למכסה שהוקצתה לו.
- **מנהל‑על** מנהל את כל הלקוחות ורואה את הצי כולו.

## התחלה מהירה

```bash
cd server
cp .env.example .env      # הגדירו JWT_SECRET וסיסמת אדמין
npm install && npm start
```

פתחו `http://localhost:8080/` (תדמית) ו‑`/console` (ניהול). מדריך פריסה מלא:
[`docs/deployment.md`](docs/deployment.md).

בניית האפליקציה: [`android/README.md`](android/README.md).
הפעלת מכשיר בשטח: [`docs/user-guide-he.md`](docs/user-guide-he.md).

## זרימת אירוע / אולם + תשלום (הליבה של המערכת)

המכשיר ננעל על **קישור ספציפי של אירוע/אולם** — לא על עמוד הבית הראשי. הזרימה:

1. בונים **ספריית קישורים** במערכת הניהול (שם + כתובת האירוע). לכל קישור אפשר
   להוסיף **דומיינים מותרים נוספים** — למשל שער התשלום (`secure.cardcom.co.il`),
   כדי שה‑checkout לא ייחסם.
2. בהוספת מכשיר בוחרים מהספרייה **איזה קישור ינעל את המכשיר**.
3. הלקוח בעמדה ממשיך **מאותו קישור** → עובר לדף התשלום → משלים.
4. לאחר סיום/חוסר פעילות, המכשיר חוזר **בדיוק לאותו קישור אירוע** (ולא לעמוד
   הראשי), מוכן ללקוח הבא. את זמן החזרה קובעים לכל מכשיר (`idle_return_seconds`,
   0 = כבוי).

הנעילה מרובת‑דומיינים: המכשיר פותח רק את דומיין האירוע + הדומיינים שהוגדרו
במפורש (שער תשלום וכו') — כל השאר חסום.

## תשלום ומכשירי סליקה פיזיים (USB)

- **סליקה אונליין (מומלץ, נתמך מלא):** התשלום מתבצע בעמוד שער התשלום בתוך ה‑WebView.
  אין צורך בקורא פיזי — רק להוסיף את דומיין השער ל"דומיינים מותרים" של הקישור.
- **מגבלה טכנית חשובה:** דף אינטרנט בתוך WebView של אנדרואיד **אינו** יכול לקרוא
  קורא כרטיסים ב‑USB ישירות (אין WebUSB ב‑WebView). קורא/מסוף EMV פיזי דורש
  אינטגרציה נייטיב עם ה‑SDK של הדגם הספציפי — נקודת הרחבה עתידית.
- **הקשחת USB (Device Owner):** בכניסה למצב קיוסק (`KioskPolicy`) נחסמים דיסק‑און‑קי
  (`DISALLOW_MOUNT_PHYSICAL_MEDIA`, `DISALLOW_USB_FILE_TRANSFER`), התקנת דרייברים/
  אפליקציות ממקור לא ידוע, safe‑boot ואיפוס — **אך קוראי כרטיסים (USB HID/מסוף)
  ממשיכים לעבוד**, כי אינם אחסון. בדיוק ההבחנה: מותר קורא סליקה, אסור דיסק‑און‑קי.

## אבטחה

הפלטפורמה בנויה לרמת אבטחה גבוהה:

- סיסמאות מוצפנות ב‑**bcrypt**; טוקני JWT לקונסולה; **טוקן ייחודי לכל מכשיר**.
- הגבלת קצב על התחברות; הפרדת תפקידים (לקוח / מנהל‑על); אכיפת בעלות על כל מכשיר.
- אכיפת מכסת מכשירים; קודי רישום חד‑פעמיים עם תפוגה.
- באפליקציה: WebView נעול לדומיין, חסימת `window.open`/`target=_blank`, Lock Task
  Mode (Device Owner), הפעלה אוטומטית ומסך נעול.
- `helmet` + CSP בשרת; `usesCleartextTraffic=false` באפליקציה (HTTPS בלבד).

> **הערה כנה על "בלתי ניתן לפריצה":** אף מערכת אינה חסינה ב‑100%. הצירוף של
> **Device Owner + HTTPS + טוקן לכל מכשיר + נעילת WebView** נותן הגנה חזקה מאוד
> ברמת המוצרים המסחריים בתחום. כדי להגיע לרמה הגבוהה ביותר בפועל יש לוודא בפריסה:
> (1) TLS אמיתי, (2) `JWT_SECRET` חזק ב‑secret store, (3) הגדרת Device Owner על כל
> מכשיר, (4) כיבוי USB debugging לאחר ההתקנה. כל אלה מתועדים במדריכים.
